Screening a suicide literature with a local model

Two prompts, one connection file, and a 27-billion-parameter model running on a laptop: every suicide-related record in both databases retrieved, screened one at a time for substantive relevance, and classified by evidence class and method — then audited twice.

What this demonstrates, and where it came from

This report exists because someone else tried the integration first and it did not go smoothly. Jonathan Singer tested the project's llms.txt connection file on a suicide-literature question, got real results, and ran into two errors along the way. Both were fixable, both were in the guide rather than the database, and this page is the same analysis run again after the fix.

The claim being tested is narrow and checkable: that an AI assistant handed one published text file can connect to these databases unaided, and that the screening work that follows — reading two thousand abstracts and deciding which are actually about suicide — can be done by a free model on a laptop rather than a commercial API. Everything below is the record of that attempt, including the parts that needed correcting.

What comes out is a corpus: 1,331 suicide-relevant records from the disciplinary journals (SWRD, 1989–2025) and the SSWR annual conference (2005–2026), each labeled Empirical or Non-empirical and, where empirical, Quantitative, Qualitative, or Review. The labels are released with the page so any individual decision can be checked.

The division of labour matters here. Three different systems did three different jobs. A coding assistant (Codex) handled retrieval — reading the connection file, writing the SQL, paginating the API, deduplicating. A local open-weight model (Qwen3.6-27B through Ollama) did all 2,034 screening decisions, because that is the volume work and it should not require a paid API. Claude was used afterwards to summarise and write up what the data showed. No single model did the whole thing, and the write-up model never touched the labels.

What broke, and what was changed

Both failures produced error messages that read like the database was misconfigured. Neither was. The fix was to the documentation, not the endpoint, and it is the reason this run went cleanly.

1. The endpoint looks missing when you GET it

The database is reached by POSTing SQL to a REST endpoint. Most assistants have a "fetch this URL" tool, and pointing it at the endpoint issues a GET, which returns 401 No API key found without a key and, with a key, 404 PGRST202 … could not find the function public.run_sql. That 404 reads as a missing function. It is not: the public. prefix is the tell that the Content-Profile header is absent, so the request is looking in the wrong schema.

The guide now tables all four request shapes against the exact response each returns, names public. as the diagnostic, and says plainly to use a shell or code tool that can POST with headers — never a page-fetch tool.

2. The sandbox prompt looks alarming

Sandboxed coding assistants ask permission before their first outbound request and display an opaque hostname. Approving kcffctxedcscvvposypb.supabase.co is the whole fix, but nothing in the guide had told the user that was the project's own hosted database.

The guide and the site now name the host to approve, state that it is read-only HTTPS on port 443, and point to the reachability probe for runtimes that have no outbound network at all.

3. "Dedupe on normalized title" was never defined

A separate round of testing surfaced a quieter problem: the guide told assistants to deduplicate double-indexed articles on normalized title without saying what normalization meant, and each run invented its own. The guide now gives the expression, scoped within publication year so that different papers sharing a generic title are not collapsed.

lower(regexp_replace(title, '[^a-zA-Z0-9]', '', 'g')) || '|' || publication_year — the rule this analysis used, which removed 8 duplicate rows from 804 SWRD matches.

None of these were database bugs, which is the point worth drawing out. An integration meant to be driven by a machine reading a text file fails at the places where that file is silent or ambiguous, and those places are only found by watching someone else's assistant hit them.

The two prompts, verbatim

The entire analysis was driven by these two instructions. They are reproduced exactly as issued, including the parts that exist only to steer an assistant away from the failure modes above.

Prompt 1 · retrieval — issued to CodexOk, do this. I want to access all papers specific to the topic of suicide: Fetch https://beperron.github.io/SocialWork-MetaData/llms.txt (or its HTML mirror at .../llms.html), run its reachability check, and connect exactly as it describes, then answer my question using those databases. The database endpoint is a POST API, not a web page, so query it from a shell or code tool rather than a page-fetch tool, and approve the host if you are asked. If you cannot fetch either URL, tell me and I will paste the file.

Three clauses in that prompt are doing specific work. "Run its reachability check" makes the assistant confirm it has outbound network before it starts writing queries. "POST API, not a web page … rather than a page-fetch tool" pre-empts failure 1. "Approve the host if you are asked" pre-empts failure 2. A user who has read the revised guide does not need to say any of this — but saying it makes the run reproducible for a reader who has not.

Prompt 2 · screening and classification — executed by local Qwen3.6-27BNow, use my local Ollama model -- Qwen3.6-27b to carefully screen each abstract for its relevance to suicide. For all relevant articles, classify as Empirical (includes systematic, meta-analysis, scoping) vs. Non-empirical. If the article is empirical, classify as qualitative, quantitative, or review (systematic, meta-analysis, scoping). Narrative reviews should all considered non-empirical. If empirical, classify as qualitative, quantitative, or review (systematic, meta-analysis, scoping). Narrative reviews should be classified as Non-empirical. Return your results as a JSON file. Just do one-by-one for most accuracy

The last five words are the substantive methodological instruction. Batching several abstracts into one request is faster and materially worse: decisions bleed across records in the same context, and a long batch drifts toward whatever label it has been emitting. One record per request costs more wall-clock time — 1.7 hours here — and buys independence between decisions.

The prompt also fixes two taxonomy boundaries that are genuinely contestable, and it is worth being explicit that these are choices rather than facts. Systematic reviews, meta-analyses, and scoping reviews count as empirical; narrative reviews do not. A different project could rule the other way and get a different corpus.

How the run actually proceeded

  1. Connect from the published file alone

    The assistant fetched llms.txt, verified it had received the complete guide by checking that it ended with END OF GUIDE, and ran the prescribed reachability probe. The probe returned HTTP/2 401 — the expected unauthenticated response, and confirmation that the runtime could reach the host at all.

    Codex · no credentials beyond the public read-only key in the guide

  2. Cast the candidate net

    A case-insensitive word-start match on the stem suicid across title and abstract, run separately against each schema. SWRD was restricted to its recommended 1989+ corpus. The API caps responses at 1,000 rows, so results were paged at 700.

    804 SWRD rows → 796 after dedup · 1,238 SSWR presentations · 2,034 unique candidates

  3. Screen every candidate, one request each

    Each record went to the local model on its own, at temperature 0 with a fixed seed and a structured JSON output schema. Every decision was appended to a checkpoint file and flushed immediately, so an interrupted run resumes without repeating work. The database's own method fields were deliberately withheld from the model — it saw only title and abstract.

    Qwen3.6-27B via Ollama · 2,034 requests · all succeeded on first attempt

  4. Audit the labels twice

    A stratified blind re-screen of 100 records, then an independent manual inspection of 20 more drawn from records the first audit had not touched. Every disagreement went to a third adjudication pass. Eight corrections were applied to the final data.

    92% blind full-label agreement · 90% on the independent check

  5. Summarise and write up

    Post-hoc analysis of the completed label set: counts, cross-tabulations, the figures on this page, and the methods narrative. Nothing at this stage altered a label.

    Claude · reading the released JSON, not the databases

Finding the candidates

The inclusion rule is deliberately mechanical, so that a reader can regenerate exactly this candidate set rather than trust that a search was thorough.

The high-recall net is a single regular expression applied to the concatenation of title and abstract:

The candidate rule(coalesce(title, '') || ' ' || coalesce(abstract, '')) ~* '\msuicid'

The word-start marker followed by the open stem catches suicide, suicidal, suicidality, and their compounds. What it deliberately does not do is treat nonsuicidal self-injury, self-harm, or euthanasia as suicide topics by default: those records enter the candidate set only if they also use a suicide-root term, and then have to survive screening on substance. The database's ranked keyword search was run separately with several phrasings — suicide prevention, suicide risk, suicidal behavior, self harm — and the first three returned nothing the stem sweep had missed.

This buys reproducibility at a known cost: a study about suicide that uses no suicide-root term anywhere in its title or abstract is invisible to the rule. That is a recall limit, not an oversight, and it is why the rule is stated rather than described.

Deduplication

A small number of SWRD articles are indexed under two journal ids, usually with differing or null DOIs, so DOI matching alone misses them. Applying the normalized-title-plus-year rule collapsed 804 SWRD rows to 796 papers. Where a group of duplicates disagreed, the retained row was chosen by preferring a record with a DOI, then the longest abstract, then the fullest author string; the discarded record ids are kept in a duplicate_record_ids field rather than thrown away.

The screening protocol

Three decisions per record, forced choices, one request each.

Relevant

Suicide is a central substantive focus or a distinctly analyzed component: ideation, attempts, deaths, suicidality, risk and protective factors, prevention, intervention, postvention, screening and assessment, bereavement and loss survivors, or attitudes, training, and policy specifically about suicide.

Suicide as one outcome among several counts only when the abstract shows it was separately analyzed or reported. Background mentions, illustrative examples, one unexamined item in a list of mental-health concerns, and unanalyzed sample characteristics do not count.

Empirical vs. Non-empirical

Empirical means the record analyzes primary or secondary observations: surveys, trials, experiments, administrative or clinical data, statistical models, interviews, focus groups, observation, qualitative text, empirical case studies, program evaluations — and, for this project, systematic reviews, meta-analyses, and scoping reviews.

Non-empirical covers narrative and traditional literature reviews, conceptual and theoretical articles, commentaries, editorials, book reviews, practice overviews, policy arguments without analyzed data, clinical vignettes without a research design, and protocols without results. A record described merely as "a review" is not empirical unless systematic methods are visible in the title or abstract.

Method, for empirical records only

Exactly one of Quantitative, Qualitative, or Review. The taxonomy the prompt specified has no mixed-methods category, so mixed-methods studies with a central quantitative component were mapped to Quantitative and the rest to their predominant method.

That is a real distortion and it is stated rather than hidden: a reader who needs a mixed-methods count cannot get one from these labels.

The cost of that configuration, measured from the per-request metrics the model returns: 2,034 requests, 1.7 hours of model time, a median of 3.3 seconds per record and 4.7 seconds at the slowest, 2.86 million prompt tokens and 49,000 completion tokens. Every record succeeded on its first attempt. No API bill, and the abstracts never left the machine — which for a suicide corpus is not merely a cost consideration.

Records without abstracts

Sixty-two records had titles and nothing else. Screening these at all is a judgment call; the alternative is dropping 3% of the corpus. They were screened from title under a conservative forced-choice rule: if a title established suicide relevance but gave no defensible evidence of an empirical design, the record was labeled Non-empirical rather than guessed into a method. Fifty-four were retained as relevant and all 54 landed in Non-empirical; eight were excluded. That rule is safe in one direction and biased in the other, and the flag screening_basis: title_only is preserved on every one of them so they can be excluded or re-screened.

Read the zero carefully. No SSWR presentation was classified Non-empirical. That is a fact about this candidate set under this protocol, not proof that the conference carries no conceptual or commentary scholarship. SSWR abstracts are structured around a research design, so the empirical signal is usually explicit in the text the model was given; a conceptual paper that reads as a study in abstract form will classify as one. It also reflects that a conference submission whose abstract shows no design is unlikely to appear in a suicide-topic sweep in the first place.

The conference also screens out more of its candidates than the journals do — 39.7% against 26.6%. Conference abstracts are longer and list more secondary measures, so a suicide item is more likely to appear somewhere in the text without being the subject of the work.

Volume over time

Both venues grow, and the right-hand edge of the chart means different things in each.

The journal series is a slow climb rather than an inflection: single digits through the early 1990s, into the teens and twenties by the 2010s, and 45 to 50 a year by 2023–2024. The conference series is steeper and starts later, holding under twenty a year until 2014 and then moving to 70–83 a year from 2024 onward. Read together they say something unremarkable but worth having a number for: suicide has become a substantially larger share of what social work researchers present and publish, and the conference registers that shift earlier than the journals do.

The 584 relevant journal articles are spread across 63 distinct journals. The concentration is modest — the largest single outlet holds 38 of them — which is consistent with suicide being a topic that appears across the discipline's specialty journals rather than one owned by a dedicated venue.

Checking the labels

A classification run of this size is only as good as its audit, and the audits here are diagnostic rather than definitive. Both are reported with their limits attached.

Blind model re-screen

A stratified sample of 100 records, 20 from each of the five outcome groups, drawn with seed 20260802. Each was re-screened by the same model, one at a time, without being shown its original label, and required to give a short rationale. Agreement was scored strictly: the whole label tuple had to match, so a record that was relevant and empirical in both passes but quantitative in one and qualitative in the other counts as a disagreement.

Ninety-two of 100 matched. All eight disagreements went to a third pass with thinking mode enabled, which saw the title, abstract, both decisions, and the blind rationales. Six of the eight were resolved against the original label and corrected; two were confirmed. That moved the corpus from 1,336 relevant records to 1,331.

What this number is not. The same model produced both passes, so 92% measures internal reproducibility under blind re-screening. It is not sensitivity, not specificity, and not agreement with a human expert. A model that is confidently and consistently wrong about a category would score well here.

Independent manual spot check

A second sample, seed 20260803, four records per group, explicitly excluding the 100 already audited. These were read against the rubric rather than resubmitted to the model. Eighteen of 20 agreed, and both disagreements were corrected:

  • Gender Differences in the Pathways from Sexual Abuse to Risky Sexual Behavior in Homeless Youth — moved from Irrelevant to Empirical–Quantitative. Suicidal ideation entered the regression as an analyzed mechanism with a separately reported significant association, which meets the relevance definition; the model treated it as an incidental covariate.
  • An Exploration of Knowledge and Attitudes about Victims or Survivors of Domestic Violence with Mental Health Disability — moved from Empirical–Qualitative to Irrelevant. Suicide and self-harm were minor items inside a broader service-needs assessment and were never distinctly analyzed.

The two corrections cancel in the relevant total and shift one record from Qualitative to Quantitative. Both errors are the same error in opposite directions: the boundary between "suicide was measured" and "suicide was analyzed" is where this rubric is hardest to apply, and it is where a reader should expect the residual error to sit.

Twenty records is a spot check, not an accuracy estimate. Four records per group gives a confidence interval wide enough to be uninformative, and the inspection was done by an AI assistant reading against the rubric, not by trained suicide researchers. Both audits also sampled equal numbers per group by design, so neither overall rate is prevalence-weighted for the corpus as a whole. A defensible accuracy claim would need independent dual human review of a larger probability sample with reported interrater agreement — which this is not, and does not claim to be.

Limitations

  • This is not a suicide-literature review. It covers selected disciplinary social work journals and one conference. Suicide scholarship in medicine, psychology, public health, sociology, and nursing is out of scope by construction, as is work by social work researchers published outside the disciplinary journal set.
  • Vocabulary-bounded recall. A record enters only if a suicide-root term appears in its title or abstract. Studies phrased entirely in alternate terminology are missing, and self-harm and nonsuicidal self-injury work is not swept in by default.
  • Abstract-level decisions. Labels come from titles and abstracts, never full texts. Distinguishing systematic from narrative review methods, or qualitative from mixed-methods designs, is sometimes impossible from an abstract, and those are exactly the cells where the audits found the most movement.
  • Sixty-two title-only records. The conservative fallback pushes them all to Non-empirical, which likely misclassifies genuinely empirical older studies. They are flagged so they can be dropped.
  • A forced taxonomy. No mixed-methods category, no case-study category. Mixed-methods work was absorbed into Quantitative or Qualitative by predominance.
  • Model dependence. One model produced every primary label and also performed the 100-record blind audit. The 92% figure is internal consistency and may well overstate agreement with independent reviewers.
  • Incomplete recent journal years. Publisher indexing lag makes SWRD 2024–2025 lower bounds; they should not carry trend conclusions.
  • Residual duplication and author ambiguity. SWRD was deduplicated on normalized title and year as the guide prescribes, but non-identical duplicates may remain, and SWRD author strings are not identity-disambiguated. SSWR author ids are canonical.

The honest summary is that this demonstrates a workable, reproducible, auditable screening pipeline that runs for free on a laptop — and that its output is a well-documented draft corpus, not a validated one. Publishing from it would require human dual review of a proper probability sample first.

Get the data and the code

Everything behind this page is in the folder it is served from: the labels, the full audit trail, and the scripts that produce them.

Data

  • suicide_abstract_screening_results.json — all 2,034 screened candidates: bibliographic metadata, abstract, the three decisions, per-request model metrics, and the pre-correction decision on every audited record.
  • suicide_relevant_articles.json — the 1,331 relevant records only.
  • suicide_corpus_labeled.csv — the same corpus as a flat table without abstracts, for spreadsheet work.
  • accuracy_audit.json — the 100-record blind re-screen, with the blind rationales and every adjudication.
  • independent_manual_spot_check.json — the 20-record independent check and its two corrections.
  • screening_summary.json — final counts and audit metadata.
  • stats.json — every number on this page, machine-readable.

Code

  • fetch_suicide_papers.py — retrieval, pagination, SWRD deduplication, and export. No credentials, no install: python3 fetch_suicide_papers.py.
  • screen_suicide_abstracts_ollama.py — the one-record-at-a-time screening pass, with the full system prompt, the output schema, and JSONL checkpointing.
  • audit_suicide_screening.py — the stratified blind re-screen and the thinking-mode adjudication of disagreements.
  • apply_independent_spot_check.py — records and applies the independent spot-check decisions with provenance.
  • compute_stats.py — recomputes every count on this page from the released labels and writes the CSV. Nothing to install.
  • make_figures.py — regenerates the three figures.
